# gRPC Employee Server with Spring Boot

This project implements a simple gRPC server using Spring Boot and Spring gRPC. The server exposes an `Employee` gRPC service that receives an employee ID and returns employee details such as ID, name, age, and salary.

## Technology Stack

- Java 17
- Spring Boot 4.0.6
- Spring gRPC
- Protocol Buffers
- Gradle

## Project Structure

```text
src/main/proto/Employee.proto
src/main/java/com/learning/grpc/GrpcApplication.java
src/main/java/com/learning/grpc/grpc/EmployeeImpl.java
src/main/java/com/learning/grpc/service/EmployeeService.java
src/main/java/com/learning/grpc/store/EmployeeStore.java
src/main/java/com/learning/grpc/Employee.java
src/main/resources/application.yaml
```

## gRPC Contract

The gRPC API is defined in `src/main/proto/Employee.proto`.

```proto
service Employee {
  rpc getEmployee (EmployeeRequest) returns (EmployeeResponse) {}
}
```

`EmployeeRequest` contains the employee ID:

```proto
message EmployeeRequest {
  int32 id = 1;
}
```

`EmployeeResponse` contains the employee details:

```proto
message EmployeeResponse {
  int32 id = 1;
  string name = 2;
  int32 age = 3;
  double salary = 4;
}
```

## Class Generation from Proto

The project uses the `com.google.protobuf` Gradle plugin configured in `build.gradle` to generate Java code from `src/main/proto/Employee.proto`.

```gradle
protobuf {
    protoc {
        artifact = 'com.google.protobuf:protoc'
    }
    plugins {
        grpc {
            artifact = 'io.grpc:protoc-gen-grpc-java'
        }
    }
    generateProtoTasks {
        all()*.plugins {
            grpc {}
        }
    }
}
```

When the project is built, Gradle runs `protoc` and generates two types of Java source files:

1. Protobuf message classes for `EmployeeRequest` and `EmployeeResponse`.
2. gRPC service classes for the `Employee` service.

For this proto file:

```proto
syntax = "proto3";
package employee.v1;
```

the generated Java package is `employee.v1`.

The important generated classes are:

| Generated class | Purpose |
|-----------------|---------|
| `employee.v1.EmployeeOuterClass` | Contains the generated protobuf message classes, including `EmployeeRequest` and `EmployeeResponse`. |
| `employee.v1.EmployeeGrpc` | Contains the generated gRPC service base class and client stubs. |
| `EmployeeGrpc.EmployeeImplBase` | Base class extended by the server implementation. |
| `EmployeeGrpc.EmployeeBlockingStub` | Blocking client stub for unary calls. |
| `EmployeeGrpc.EmployeeStub` | Asynchronous client stub. |
| `EmployeeGrpc.EmployeeFutureStub` | Future-based client stub. |

The generated sources are created under the Gradle build directory, typically:

```text
build/generated/source/proto/main/java
build/generated/source/proto/main/grpc
```

These generated files should not be edited manually. Any API changes should be made in `src/main/proto/Employee.proto`, then regenerated by running:

```bash
./gradlew generateProto
```

The server implementation uses these generated classes here:

```java
public class EmployeeImpl extends EmployeeGrpc.EmployeeImplBase
```

and builds the response using:

```java
EmployeeOuterClass.EmployeeResponse.newBuilder()
```

## Implementation Overview

### Application Entry Point

`GrpcApplication` starts the Spring Boot application:

```java
SpringApplication.run(GrpcApplication.class, args);
```

Spring Boot scans the project packages, creates the required beans, and starts the embedded gRPC server.

### gRPC Server Implementation

`EmployeeImpl` is the gRPC service implementation.

It extends the generated `EmployeeGrpc.EmployeeImplBase` class and overrides the `getEmployee` RPC method. The class is annotated with `@GrpcService`, which registers it as a gRPC service in the Spring application context.

Request flow:

1. A gRPC client calls `getEmployee` with an employee ID.
2. `EmployeeImpl.getEmployee()` receives the request.
3. The implementation calls `EmployeeService.getEmployee(id)`.
4. The response is sent back using `responseObserver.onNext(response)`.
5. The RPC is completed using `responseObserver.onCompleted()`.
6. If an exception occurs, it is logged and sent to the client using `responseObserver.onError(e)`.

### Business Service Layer

`EmployeeService` contains the application logic for fetching employee data.

It loads employees from `EmployeeStore`, finds the employee by ID, and converts the domain object into a protobuf `EmployeeResponse`:

```java
EmployeeOuterClass.EmployeeResponse.newBuilder()
    .setId(employee.id())
    .setName(employee.name())
    .setAge(employee.age())
    .setSalary(employee.salary())
    .build();
```

### In-Memory Data Store

`EmployeeStore` is a simple in-memory store backed by a `HashMap`.

The `loadEmployees()` method adds sample employee records:

| ID | Name    | Age | Salary |
|----|---------|-----|--------|
| 1  | John    | 28  | 80000  |
| 2  | Jane    | 35  | 120000 |
| 3  | Rahul   | 20  | 30000  |
| 4  | Jenifer | 25  | 50000  |
| 5  | Pablo   | 23  | 40000  |

The `getEmployee(int id)` method returns the employee matching the requested ID.

### Server Configuration

The gRPC server port is configured in `src/main/resources/application.yaml`:

```yaml
spring:
  application:
    name: grpc
  grpc:
    server:
      port: 9090
```

The server runs on port `9090`.

## How It Works

The complete request lifecycle is:

```text
gRPC Client
    |
    | getEmployee(EmployeeRequest{id})
    v
EmployeeImpl
    |
    | calls EmployeeService
    v
EmployeeService
    |
    | loads and reads employee data
    v
EmployeeStore
    |
    | returns Employee record
    v
EmployeeService
    |
    | builds EmployeeResponse
    v
EmployeeImpl
    |
    | sends response through StreamObserver
    v
gRPC Client
```

This project currently implements a unary RPC, meaning the client sends one request and receives one response.

## Build the Project

Use the Gradle wrapper:

```bash
./gradlew build
```

This compiles the Java code, generates protobuf/gRPC Java sources, and runs the tests.

## Run the Server

```bash
./gradlew bootRun
```

After startup, the gRPC server listens on:

```text
localhost:9090
```

## Example Request

If `grpcurl` is installed, you can call the service like this:

```bash
grpcurl -plaintext \
  -d '{"id": 1}' \
  localhost:9090 \
  employee.v1.Employee/getEmployee
```

Expected response:

```json
{
  "id": 1,
  "name": "John",
  "age": 28,
  "salary": 80000
}
```

## Notes

- Employee data is stored in memory and is recreated by `EmployeeStore.loadEmployees()`.
- There is no database integration in the current implementation.
- Invalid or missing employee IDs are not currently handled with a custom gRPC status response.
- The `.proto` file is the source of truth for the gRPC API contract.
